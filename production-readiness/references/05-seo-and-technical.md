# 5. SEO and technical hygiene

Last verified: 2026-11-02. Static SPA hosting assumed (no server-side rendering), which shapes several trade-offs.

## Keep it closed until launch day

- A **build-time switch** (for example `VITE_ALLOW_INDEXING=true`) controls the robots meta tag and `robots.txt`. Unset: `noindex, nofollow` in the HTML and `Disallow: /` in `robots.txt`. Set: normal files. The switch must match **exact text**, so a typo cannot open the site.
- A matching **server switch** for the dynamic sitemap (returns 404 until enabled) and an `X-Robots-Tag: noindex` header on every API response.
- Document how to open the site: set both switches, redeploy the site, run the smoke script with its "indexable" option.
- Gotcha: a crawler blocked by `robots.txt` cannot see a `noindex` meta tag. That is fine before launch. But some verification crawlers (for example an OAuth brand review) may need your homepage, privacy and terms pages to be fetchable; if so, open only those three paths in the closed `robots.txt`.

## Per-page metadata

- One mechanism (a hook or component) sets `<title>`, description (≤160 chars), canonical URL, Open Graph and Twitter tags, and robots per route. Private pages (login, register, account, 404, system status) get `noindex`.
- Canonical points to the **canonical host** (decide apex vs `www` once; redirect the other).
- One `H1` per page, and every image has meaningful `alt`. Audit with a test that renders each public route.
- Default social image: generic brand image until the owner supplies one; keep it as a replaceable file.

## Structured data

Minimal and true: `Organization`/`WebSite` on the home page, and `Book` (or your content type) only with fields the owner actually entered. No invented authors, dates or ratings, and **no `AggregateRating`** unless real, verifiable ratings exist.

## Sitemap and robots

- Dynamic `sitemap.xml` generated by the API from published, public content only (never admin, panel, account or signed-link routes), proxied to `/sitemap.xml` and declared in `robots.txt` only when indexing is on.
- AI-training crawlers: allowing or blocking them is a **content-owner decision**. Put the commented block in the template and let the owner choose.
- `llms.txt`: optional and low priority; do not add without the owner's approval.

## Real 404s on a static host

A catch-all `/* → /index.html` rewrite returns 200 for every URL (a "soft 404"). Instead, list every real application route as its own rewrite, add a `404.html`, and let the host serve it with status 404 for the rest. Keep one source of truth for routes (a route-list file) and a **test that fails when the router and the rewrite list drift**. Limitation to accept and document: a dynamic URL that matches a rule but does not exist (for example `/books/does-not-exist`) still returns 200 from the host; the app shows "not found" with `noindex`.

## Console errors for anonymous visitors

Each anonymous visit often triggers `GET /me` and `POST /auth/refresh` returning 401. Avoid it without weakening security with a **session-hint cookie** (see phase 1) set on login and cleared on logout; skip those calls when it is absent. Add an E2E assertion of zero 401 responses while browsing several pages signed out.

## Build hygiene

- No source maps in the production build; a test compiles the app and fails if a `.map` appears.
- Icons: SVG favicon plus PNG sizes (32, 192, 512), `apple-touch-icon`, and a basic web manifest.
- Heavy or decorative code loaded on demand; one stable inline script so a content-security-policy hash does not change.
- Cache `/assets/*` (hashed names) for a year as immutable.
- Do not chase Lighthouse numbers until the design is final; measure once at the end.

## Content-Security-Policy

Start in **report-only** with a tiny report endpoint that stores only the violated directive and blocked resource (no IP, page URL or user agent; cap size and count). Compute the policy from the built output (script hashes) and test that the checked-in value matches. Account for: third-party sign-in script and iframe, your media CDN for images/video, inline styles from your CSS framework, and upload endpoints. Disable CDN features that rewrite inline scripts (auto-minify, rocket loader) or the hash will stop matching. Review reports for one or two weeks before deciding to enforce; rich-text content that allows images from anywhere conflicts with an image allow-list, so decide which side gives.
